Your server

You need a Corteza server. The one in our install video, on Elestio (1 CPU, 1 GB, 25 GB, about $13 a month), is comfortable with about 8,000 records, for example 1,000 grants with their payments, requirements, organizations and contacts, and usable to about 20,000; its disk holds about 20,000 one-megabyte documents. Beyond that, pages slow down. In our test a server with two processors (about $40 a month at Elestio) kept pages quick for five people at 5,000 grants, while doubling only the memory did not help. Prices vary by host. The software is free.

Before you install (both required)

Some settings apply to the whole Corteza server, not only to OwnFMS.works.

Free, open-source software under the Apache 2.0 licence.

What the setup changes on your server
  • Navigation. It writes a stylesheet and a small script that add a top bar of page links and hide the left sidebar in the Compose app. It replaces the server's existing custom CSS and code snippets.
  • Default access. It removes the read access every signed-in user has by default, so people see only what their role grants. It also masks other people's email addresses from signed-in users. Names stay visible, so a record's History can show who made a change.
  • Roles. It creates Staff, Manager and Demo Viewer, and gives the built-in Administrator role the page-layout permissions the build needs.
  • Data model. Nine modules plus a read-only Change Log, with duplicate rules (organization name and EIN, contact email, grant reference number, program and fiscal-period names, initiative title), default values (a new grant starts as Draft) and an EIN format check (12-3456789).
  • Landing page. People who hold only the Staff, Manager or Demo Viewer role are sent straight to the OwnFMS.works Home page when they open the server's front page. Administrators keep Corteza's own screens. It also hides the Jitsi video tile from these three roles.

    Next steps

    1. Revoke the setup client: open Admin > Auth Clients, untick Enabled, save, then delete. Expiry dates are not enforced for these keys, and the key can act as an administrator.
    2. Set up outgoing e-mail: the server has no usable e-mail server yet, so Forgot password and e-mail sign-in codes will not work. Enter your host's SMTP details in the admin area under Settings, Email, or ask your host.
    3. Add your people: in Admin > Users make a user for each person with the Staff or Manager role, and give the administrator login to nobody. Change or remove the sample sign-ins before real people use the server.
    4. Switch on multi-factor authentication for the administrator: your server's address followed by /auth/security.
    5. Back up the server (a snapshot from your host is enough) before you enter real records, and check that your host's daily backups are on.
    6. Document uploads are off, because on every Corteza 2024.9 release a file attached to a record can be downloaded by anyone who has its link (CVE-2026-108729). Keep such documents where they are and note the location in the record. When Corteza ships the fix, run the installer again with Allow document uploads ticked.
    7. Optional, and recommended: schedule the small job that keeps the calculated fields current (automatic reference numbers, due flags, budget status, the payments check, possible-duplicate marks and each grant's History tab). It is run_jobs.py in the starter; the README has a section called "Keeping it up to date". Without it everything else works, but those fields stay empty.
