Install OwnFMS.works

This page sets up the OwnFMS.works starter on your own Corteza server: nine modules for managing grants, their pages, three roles, a dashboard and, if you want it, a small set of fictional sample data. It does the same work as the Python scripts, without installing anything on your computer. It is safe to run twice: whatever already exists is reused.

This page was opened from a file on your computer. Most servers refuse requests from such a page, so the connection may fail. If it does, put this file on an https address you control, or use the Python scripts or the Colab notebook instead.

Your client secret stays in this page and is sent only to your own server. It is not stored.

Your server

The address of your Corteza server, starting with https://

From the setup client you created in the Corteza admin area (Auth Clients, type client_credentials).

The page installs, runs the checks, and then turns the setup key off and deletes it, so it cannot be used again. If the checks fail, it keeps the key so you can repair and try again. After the key is revoked, Test connection and Run checks no longer work with it, which is why the checks run first.

Expiry dates are not enforced for these keys. To revoke by hand: open Admin > Auth Clients, untick Enabled, save, then delete.

Options

Fictional organizations, grants, payments and requirements, so there is something to look at.

Optional. A sign-in is created only when you type a password for it. Leave a box empty to skip that sign-in. The addresses are staff@ownfms.example, manager@ownfms.example and demo@ownfms.example.

Before you install

Required to install. Some settings apply to the whole Corteza server, not only to OwnFMS.works.

What the setup changes on your server
  • Navigation. It writes a stylesheet and a small script that add a top bar of page links and hide the left sidebar in the Compose app. It replaces the server's existing custom CSS and code snippets.
  • Default access. It removes the read access every signed-in user has by default, so people see only what their role grants. It also masks other people's email addresses from signed-in users. Names stay visible, so a record's History can show who made a change.
  • Roles. It creates Staff, Manager and Demo Viewer, and gives the built-in Administrator role the page-layout permissions the build needs.
  • Landing page. People who hold only the Staff, Manager or Demo Viewer role are sent straight to the OwnFMS.works Home page when they open the server's front page. Administrators keep Corteza's own screens. It also hides the Jitsi video tile from these three roles.

Tick the box above to confirm, then press Install.
